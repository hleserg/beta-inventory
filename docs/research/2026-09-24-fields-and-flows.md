# Поля, сценарии, метки: что взять у готовых

Выжимка трёх поисков 24.09.2026. Итоги по рынку лежат в
[prior-art](2026-09-24-prior-art.md), здесь их не повторяем. Решения, которые
отсюда вытекают, собраны в [манифесте](../manifesto.md).

## Поля профиля «DIY-электроника»

Ниже поля, которые стоит добавить к профилю `default.yaml`. Звёздочка
помечает поле, которое агент заполняет сам по названию чипа.

| Тип | Обязательно | Желательно |
|---|---|---|
| Все модули | чип*, питание*, распиновка* | логический уровень* (3,3 / 5 / оба), интерфейс* (I2C / SPI / UART / 1-Wire / аналог), адрес I2C* (`0x76`), ссылка на ESPHome / Arduino* |
| Модуль питания (понижайка, повышайка, зарядка, защита) — **новый тип** | вход, В*; выход, В*; ток, А* | КПД, регулировка (подстроечник / фикс.) |
| Микроконтроллерный модуль | чип*, питание*, распиновка* | радио* (Wi-Fi / BLE / LoRa), flash / PSRAM*, USB (CH340 / нативный) |
| Аккумуляторы и батарейки — **новый тип** | химия (Li-ion / LiPo / NiMH / щелочь), напряжение, ёмкость | разъём, защита встроена |
| Резистор, конденсатор | номинал (уже есть) | допуск, напряжение (у конденсатора уже есть) |
| Разъём | серия, шаг, контактов (уже есть) | папа / мама |

Адрес I2C, чип и интерфейс получают вес в поиске. «Что у меня на 0x76»
и «есть ли что-то на SPI» — вопросы, которые задаёт агент при подборе
деталей под проект.

## Удачные решения, которые берём

1. **«Количество неизвестно»** (Part-DB, флаг у партии). Резисторы и
   перемычки никто считать не будет. «Есть, не считал» лучше выдуманного
   числа и не ломает остатки.
2. **Своя единица у позиции** (PartsBox): штуки, метры провода, граммы
   припоя, миллилитры краски. Без этого не обойтись профилям других хобби.
3. **Поля от категории** (InvenTree, шаблоны параметров). У нас это уже
   есть: категория → тип, поля наследуются.
4. **Автозаполнение по названию** (Part-DB и Binner тянут данные из LCSC,
   Mouser, DigiKey). У нас эту роль играет агент: он ищет по чипу даташит,
   распиновку и адрес. Встраивать API поставщиков не нужно, а AliExpress они
   всё равно не покрывают.

## Чего не берём

1. **Админка из справочников и таблиц на 20 столбцов** (Part-DB). Отпугивает
   всех, кроме профессионалов.
2. **Производство**: партии, сборки, поставщики с ценами, BOM с вариантами
   (InvenTree, BOMIST). Для одного человека в гараже это бюрократия.
3. **Закрытый набор полей** (Itemtopia). Люди всё равно просят свои поля.

## Сценарии: что подсмотрели

| Сценарий | Кто решил хорошо или плохо | Как делаем у себя |
|---|---|---|
| Переложить | InvenTree переносит одним действием. В Snipe-IT это два действия, и люди просят «перенос» годами ([#8280](https://github.com/grokability/snipe-it/issues/8280)) | «В руке» → коробка: одно действие, одна запись в истории |
| Высыпал и пересчитал | InvenTree: «пересчёт» задаёт абсолютное число, а разницу пишет в историю | Сейчас «Освободить коробку» и «положить N». Потом кнопка «пересчёт» |
| Записать ссылку в NFC | Homebox: ссылку для метки копируют руками из адресной строки ([#441](https://github.com/sysadminsmedia/homebox/issues/441)) | Рядом с QR — ссылка текстом и кнопка «скопировать» |
| Понятная модель | Grocy: не ясно, как связаны остатки, меню и список покупок ([#717](https://github.com/grocy/grocy/issues/717)) | Одно правило: любое изменение количества — движение в истории |
| Бэкап | Grocy и Homebox: один файл базы | Копия папки данных. Кнопка «скачать архив» — потом |

Отвергли: таблицу заказов с датами прихода (у нас это коробка «В пути»),
поиск по штрихкоду в OpenFoodFacts (у модулей с Али штрихкодов нет), ID с
префиксом категории (при перекладке категория коробки меняется, а ID —
нет).

## Метки и телефоны

- **Android** читает NDEF-ссылку сам и открывает браузер.
- **iPhone** (XS и новее) читает метку в фоне и показывает уведомление. По
  нажатию открывается Safari. Приложение не нужно.
- **Регистр.** Заглавные буквы нужны только QR: так он получается мельче.
  В NFC ссылку пишем обычным префиксом `http://` из NFC Tools, строчными.
  Сервер регистр не различает.
- **Web NFC** (чтение метки кнопкой на странице) работает только в Chrome
  на Android и только по HTTPS ([Chrome](https://developer.chrome.com/docs/capabilities/nfc)),
  поэтому его не делаем.
- **Считыватель на коробке.** Схема [adonno/tagreader](https://github.com/adonno/tagreader):
  D1 mini (ESP8266), PN532 и пищалка, прошивка на ESPHome, изначально для
  Home Assistant. PN532 в ESPHome читает и пишет NDEF, поэтому ID
  достаётся из той же ссылки, что и для телефона. Притвориться меткой
  (эмуляция) он не может ([ESPHome PN532](https://esphome.io/components/binary_sensor/pn532/)).
  Wi-Fi настраивается штатно: запасная точка доступа плюс `captive_portal`.
- **Метки на металле.** На клещи и другой металл нужна NFC-метка с
  ферритовой подложкой (on-metal). Обычную там не прочитать.
- **UHF** (EPC Gen2, 866–868 МГц): в реальном ящике видно на 1–3 м, модуль
  вроде YRM100 стоит около 4500 ₽, метки для металла — 15–80 ₽. Телефон UHF
  не читает. Нужна антенна или считыватель на каждый ящик, выходит 6–8
  тыс. ₽ за ящик.
